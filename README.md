# Claude Autonomous Lab — Full Project

This is a **complete, private, language-agnostic** repository that runs a fully autonomous,
Claude-only multi-agent workflow with:
- Framework bootstrap & context-engineering
- UX research/design → Architecture → Council → Planning → Coding (FE/BE/DevOps) → Test
- Learning loop (experiments + patterns + benefit reports)
- Local runner for **auto-commit** (with optional **auto-push** toggle)
- GitHub Actions CI for validation

## Quick Start
1) Open this folder in **Claude Desktop** (or Claude Code) so agents can read/write files.
2) (macOS) Install `fswatch` and `jq` if you want the runner: `brew install fswatch jq`
3) Start local runner:
   ```bash
   bash runner/runner.sh
   ```
   On Windows (PowerShell):
   ```powershell
   .\runner\runner.ps1
   ```
4) In Claude, say:
   > "Use the orchestrator to build a small *calculator* web app. Verbosity=audit."
5) The system will write artifacts to `/artifacts`, update `/contracts`, generate code in `/src`, and commit locally.
6) To enable auto-push to GitHub later, set `"auto_push": true` in `runner/runner.config.json`.

## Repo layout
- `agents/` — Agent manifests for orchestrator + SDLC + learning
- `flows/` — Orchestration state machine
- `artifacts/` — All structured outputs + schemas
- `contracts/` — System & interface definitions (generated by agents)
- `policies/` — Context budgets, quality gates, toggles
- `runner/` — Local file watcher, validator, and Git integration
- `src/` — Language-agnostic sample app scaffold (FE/BE/Shared)
- `runs/` — Learning artifacts (patterns, benefit report)
- `.github/workflows/` — CI validation

> This repo is **language-neutral**. You can replace the sample scaffold with any stack.


# 🧠 Claude Autonomous Lab  
**A fully Claude-native, self-orchestrating, context-engineered development framework**

---

## 📘 Overview

**Claude Autonomous Lab** is an **AI-native software engineering framework** that allows multiple Claude agents to **design, plan, code, test, learn, and evolve** autonomously — without any external runtime, backend, or API.

It’s a **language-agnostic**, **self-contained**, and **context-engineered** ecosystem designed to operate entirely inside Claude environments (Claude Desktop, Claude Code, or Claude Web).

Unlike traditional frameworks that depend on Python or Java runtimes, the Claude Autonomous Lab makes **Claude itself the execution engine** — all reasoning, coordination, and decision-making happen through natural language and structured files.

---

## 🧩 Core Concept — Independent Runner with Autonomous Agents

Claude Autonomous Lab separates **reasoning** from **execution**, creating a self-sufficient environment where:

- **Agents** perform reasoning (design, planning, architecture, coding).  
- **Runner** performs automation (file I/O, validation, commits, Git sync).  
- **Policies** enforce governance and context safety.

This design makes the framework **independent** — it runs with no continuous runtime or daemon process.  
Claude can read, modify, and evolve the repository by itself using the provided manifest and structure.

## 🧠 Context Engineering & Learning

Each time Claude completes a cycle:
- Results are saved in `/artifacts` and `/runs/`
- `learned_patterns.json` tracks what worked  
- `benefit_report.json` measures improvements  

On the next run, the **orchestrator** references these files to:
- adjust context prioritization,  
- refine agent parameters,  
- improve reasoning flow automatically.  

This means the system *learns by doing*, without retraining or retriggering an external LLM.

---

## 💡 Why It’s Independent

This framework **does not rely on a continuous server or runtime**.  
Instead, it uses:
- **Claude** for reasoning and generation  
- **Filesystem + Git** for persistence  
- **Runner** for automation  

Everything happens locally.  
Claude reads manifests, applies reasoning, and updates artifacts.  
The runner validates and commits these changes.  
This makes the system fully **offline-capable, reproducible, and auditable**.

**Claude is both the developer and the orchestrator — no hidden runtime.**

## 🔒 Configuration

### runner/runner.config.json
```json
{
  "auto_push": false,
  "commit_message_prefix": "auto: agent update"
}
```
- `auto_push`: if true, runner pushes after every commit.  
- `commit_message_prefix`: custom prefix for automated commits.

## 🔍 Validation and CI

GitHub Actions (`.github/workflows/ci.yml`) ensures that every commit:
- validates schema integrity,  
- runs lightweight checks,  
- logs validation output,  
- and confirms that agents generated valid artifacts.

## 🧩 Design Philosophy

1. **Autonomy First** – Claude manages the full software lifecycle.  
2. **Transparency Always** – Every artifact and decision is human-readable.  
3. **Safety by Policy** – HITL and schema rules prevent unsafe behavior.  
4. **Learning by Context** – Agents learn from structured experience, not retraining.  
5. **Human Optional** – You can let it run, or intervene at any stage.

## 🧭 For Claude AI Agents

### Behavior Guidelines:
- Always check `/flows` before acting — they define task order.  
- Validate outputs against `/artifacts/schemas` before writing.  
- When uncertain, consult `/policies/context-governance.json`.  
- Update `/runs/benefit_report.json` after every improvement.  
- Never modify code outside of `/src`, `/contracts`, or `/artifacts`.  

This ensures safety, version consistency, and maintainability.
